# Checklist de qualidade

## Uso de skills

- [ ] `/design-taste-frontend` foi usado ou considerado para definir direção visual quando o projeto era landing, portfolio ou redesign.
- [ ] `/redesign-existing-projects` foi usado quando havia site/app/código existente.
- [ ] `/suggest-improvements` foi usado ou considerado quando a tipografia ainda não estava definida.
- [ ] `/find-animation-opportunities` foi usado ou considerado antes de adicionar animações em várias seções.
- [ ] `/apple-design` ou `/emil-design-eng` foi usado para calibrar microinterações, springs, gestures ou sensação de resposta quando o projeto tinha motion relevante.
- [ ] `/pick-ui-library` foi usado antes de adicionar bibliotecas novas para componentes complexos.
- [ ] `/audit-typography` foi usado na revisão de tipografia quando havia implementação para auditar.
- [ ] `/review-animations` ou `/improve-animations` foi usado na revisão de motion antes da entrega quando havia animações relevantes.
- [ ] `/impeccable audit` ou `/impeccable polish` foi usado ou considerado no acabamento final.

## Estratégia

- [ ] Objetivo e público estão claros.
- [ ] O CTA principal aparece no hero e em pontos estratégicos.
- [ ] A página responde às principais objeções.
- [ ] Nenhuma informação comercial foi inventada.
- [ ] Projetos conceituais estão identificados corretamente.

## Visual

- [ ] O primeiro recorte apresentou nav + hero + 2ª seção antes do restante, quando aplicável.
- [ ] Foram criadas 4 variantes de hero realmente distintas com seletor visível na versão de apresentação.
- [ ] A variante final de hero foi escolhida, e o seletor foi removido antes da publicação final quando não fizer parte do produto.
- [ ] O site não parece um template genérico.
- [ ] Hierarquia tipográfica consistente.
- [ ] Paleta e contraste coerentes.
- [ ] Imagens e vídeos têm qualidade suficiente.
- [ ] Espaçamento funciona em toda a página.
- [ ] Não há seções repetitivas sem função.
- [ ] Todos os componentes possuem estados de interação.

## Motion

- [ ] Hero possui entrada bem dirigida e com função clara.
- [ ] Seções importantes possuem animação coerente.
- [ ] Há microinterações em CTAs, cards e navegação.
- [ ] Animações não prejudicam leitura.
- [ ] Animações frequentes são rápidas, discretas e não cansam.
- [ ] Gestures, drawers, sheets e sliders respondem imediatamente ao input quando existirem.
- [ ] `prefers-reduced-motion` foi respeitado.

## Responsividade

- [ ] 375 px revisado.
- [ ] 768 px revisado.
- [ ] 1440 px revisado.
- [ ] Sem overflow horizontal.
- [ ] Menu mobile funciona.
- [ ] Formulários funcionam no celular.
- [ ] Vídeos e imagens mantêm enquadramento.

## Funcionalidade

- [ ] Links internos levam a IDs existentes.
- [ ] WhatsApp está correto.
- [ ] Telefone usa `tel:`.
- [ ] E-mail usa `mailto:`.
- [ ] Formulários possuem comportamento definido.
- [ ] Nenhum botão principal está sem ação.
- [ ] Não existem placeholders na entrega.

## SEO e compartilhamento

- [ ] Título e descrição.
- [ ] Canonical.
- [ ] Favicon.
- [ ] Ícone para celular.
- [ ] Open Graph.
- [ ] Twitter Card.
- [ ] Imagem social.
- [ ] Sitemap.
- [ ] Robots.
- [ ] Manifesto.
- [ ] Dados estruturados verdadeiros.
- [ ] `lang` correto.
- [ ] Headings semânticos.
- [ ] Alt text.

## Código e entrega

- [ ] Conteúdo centralizado.
- [ ] Componentes modulares.
- [ ] Build concluído sem erro.
- [ ] Console sem erros críticos.
- [ ] ZIP final organizado.
- [ ] Instruções de instalação.
- [ ] URL publicada validada.
- [ ] Pendências externas documentadas.
